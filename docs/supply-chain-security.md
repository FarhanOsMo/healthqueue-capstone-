# Supply chain security summary (SLSA alignment)

**Bottom line for the CTO:** HealthQueue's pipeline is *designed* to produce SLSA Build Level 2 artifacts
(signed provenance generated by a hosted build platform). That claim becomes **verified** only after the release
workflow has run on GitHub and `gh attestation verify` passes for a published image. Until then the project claims
**no SLSA level**. Everything below says exactly what is implemented, what was tested, and what is still planned.

References: [SLSA v1.2 specification](https://slsa.dev/spec/v1.2/) (Build track: L1 provenance exists; L2 signed
provenance from a hosted build platform; L3 hardened, isolated build platform; v1.2 re-introduces a Source track),
and GitHub's docs: *artifact attestations by themselves provide SLSA v1 Build L2; reusable workflows that isolate the
build can reach Build L3*
([GitHub Docs](https://docs.github.com/en/actions/concepts/security/artifact-attestations)).

## 2. SLSA mapping

### Build track

| SLSA v1.x requirement | What HealthQueue does | Level satisfied? |
|---|---|---|
| **L1** - consistent build process; provenance exists and is distributed | Scripted builds (Dockerfile + workflow); provenance generated (GitHub attestation in CI; local demo provenance) | 🟡 by design in CI; local demo only proves the mechanism |
| **L2** - build runs on a **hosted** build platform that **generates and signs** provenance | GitHub-hosted runners + `attest-build-provenance` (Sigstore-signed) + `gh attestation verify` | 🟡 **designed for L2**; verified only after the first tagged release run |
| **L3** - hardened platform: builds isolated from each other; signing material not accessible to user-defined build steps | Ephemeral runners give isolation, but our build steps and the attestation run in the **same** job | ❌ not met. Path: move the build into a **reusable workflow** (GitHub's documented route to Build L3) and verify `--signer-workflow` against it |

### Source track (SLSA v1.2)

| Requirement area | Status |
|---|---|
| Version control with history (Git, GitHub) | ✅ |
| Changes reviewed before merge; protected branch; enforced via platform settings | 🟡 files present, GitHub settings must be enabled |
| Source provenance / verified source attestations | 🔵 not implemented |

No Source-track level is claimed.

## 3. How a release is verified (for anyone, not just CI)

```bash
IMAGE=ghcr.io/farhanosmo/healthqueue-api@sha256:<digest-from-the-gitops-PR>

# 1. Signature: must come from THIS repo's release workflow on a tag
cosign verify "$IMAGE" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github.com/FarhanOsMo/healthqueue-capstone-/\.github/workflows/release\.yml@refs/tags/v'

# 2. SBOM attestation
cosign verify-attestation "$IMAGE" --type spdxjson \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github.com/FarhanOsMo/healthqueue-capstone-/\.github/workflows/release\.yml@refs/tags/v'

# 3. SLSA build provenance (GitHub artifact attestation)
gh attestation verify "oci://$IMAGE" --repo FarhanOsMo/healthqueue-capstone- \
  --signer-workflow FarhanOsMo/healthqueue-capstone-/.github/workflows/release.yml
```

Local, free equivalent (no GitHub needed): `bash scripts/local_supply_chain.sh`.

## 4. Release process (step by step)

1. Changes merge to `main` through reviewed PRs with green CI.
2. A maintainer tags: `git tag v0.1.1 && git push origin v0.1.1`.
3. `release.yml`: tests -> build -> **Trivy gate** -> push to GHCR -> **SBOM** -> **sign** -> **attest SBOM** ->
   **provenance** -> **verify all three** -> upload evidence (90-day retention; optional S3 archive via OIDC).
4. The workflow opens a PR changing `deploy/k8s/overlays/production/kustomization.yaml` to the verified digest.
5. A reviewer merges; Argo CD syncs. Rollback = revert that PR.

## 5. Costs and limits (why this stays $0)

GHCR storage and bandwidth for **public** packages, GitHub Actions minutes for **public** repositories on standard
runners, and the Sigstore public-good instance are free; artifact attestations are available for public
repositories. Note that the signature and provenance are written to the **public** Rekor transparency log - fine for
an open-source capstone, but a private product would review that. If the repository were private, attestations
need GitHub Enterprise Cloud and Actions minutes are capped - see [COST_AND_PREREQUISITES.md](COST_AND_PREREQUISITES.md).
