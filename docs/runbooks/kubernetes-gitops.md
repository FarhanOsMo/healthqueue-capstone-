# Kubernetes + GitOps: deploy, update, roll back, troubleshoot, clean up

All commands run from the repository root in **Git Bash** (Windows) or any shell (macOS/Linux). The cluster gets its
own kubeconfig, so first:

```bash
export KUBECONFIG="$PWD/.kube/healthqueue.kubeconfig"    # Git Bash on Windows: export KUBECONFIG="$(pwd -W)/.kube/healthqueue.kubeconfig"
```

## 1. Bring up the platform (once, ~10-15 min first time)

```bash
bash scripts/kind_up.sh              # kind cluster "healthqueue" + registry trust + Argo CD v3.5.5 + Gitea + DB secret
bash scripts/local_supply_chain.sh   # build -> push to local registry -> Trivy -> SBOM -> sign -> verify
bash scripts/set_image.sh local      # pin overlays/local to the digest the pipeline just signed
bash scripts/gitops_publish.sh "initial deploy"   # push manifests to Gitea + register the Argo CD app, wait for Synced/Healthy
curl http://127.0.0.1:30080/healthz
```

The database password is generated by `kind_up.sh` into the Secret `healthqueue-db` and is **never** in Git. To
recreate it: `kubectl -n healthqueue create secret generic healthqueue-db --from-literal=POSTGRES_PASSWORD=$(openssl rand -hex 16)`
(then restart the StatefulSet only if the volume is new - Postgres keeps the original password in its data).

## 2. Verify reconciliation

```bash
bash scripts/gitops_verify.sh        # 14 checks; evidence in reports/k8s/gitops-verification.txt
kubectl -n argocd get applications
kubectl -n healthqueue get deploy,sts,pods,svc,networkpolicy,pdb
```

Argo CD UI: `kubectl -n argocd port-forward svc/argocd-server 8443:443` -> https://localhost:8443, user `admin`,
password: `kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d`.

Gitea UI (pull requests for the demo): `kubectl -n gitops-local port-forward svc/gitea-http 3000:3000` ->
http://localhost:3000, user `hq-admin`, password in `.local/gitea-admin-password`.

## 3. Change management (pull-request based)

* **Production / GitHub:** branch -> edit `deploy/` -> PR -> CI validates (kubeconform, yamllint) -> review -> merge ->
  Argo CD syncs. Release images arrive as PRs opened by `release.yml` that pin a verified digest.
* **Local demo:** edit -> `bash scripts/gitops_publish.sh "message"` (commits to the git-ignored worktree, pushes to
  Gitea). To show a PR, push a branch to Gitea and open the PR in the Gitea UI, then merge it there.

## 4. Image update

```bash
APP_VERSION=0.1.2 bash scripts/local_supply_chain.sh   # new digest, scanned + signed + verified
bash scripts/set_image.sh local                        # edits overlays/local/kustomization.yaml (a Git change)
bash scripts/gitops_publish.sh "deploy 0.1.2"          # Argo CD rolls it out (maxUnavailable 0)
```
Performed for real on 2026-10-17: v0.1.0 -> v0.1.1 (connection pool) - `reports/k8s/gitops-image-update.txt`.

## 5. Rollback

```bash
git -C .local/gitops-worktree revert --no-edit HEAD && bash scripts/gitops_publish.sh   # local
git revert <sha> && git push                                                            # GitHub flow
```
Argo CD history also allows a UI rollback, but with auto-sync on, **Git is the source of truth** - revert in Git.

## 6. Troubleshooting

| Symptom | Check | Fix |
|---|---|---|
| App `OutOfSync` and stays so | `kubectl -n argocd get app healthqueue-local -o yaml` -> `status.conditions` | fix the manifest error in Git |
| `ComparisonError ... repository not found` | Gitea pod running? `kubectl -n gitops-local get pods` | re-run `gitops_publish.sh` (Gitea data is on a PVC) |
| `ImagePullBackOff` | `kubectl describe pod` | registry container running? `docker start kind-registry`; digest pushed? |
| Pods `CreateContainerConfigError` | Secret `healthqueue-db` missing | recreate (section 1) |
| Pod rejected: `violates PodSecurity "restricted"` | securityContext in the change | add runAsNonRoot / drop ALL / seccomp |
| API cannot reach DB after a policy change | `kubectl -n healthqueue get networkpolicy` | DB ingress must allow `app.kubernetes.io/name: healthqueue-api` |
| Port 30080 not answering | `docker ps` -> `healthqueue-control-plane` | cluster stopped: `docker start healthqueue-control-plane` |
| kubectl talks to the wrong cluster | `kubectl config current-context` | `export KUBECONFIG=...healthqueue.kubeconfig` |

## 7. Clean up (only this project's resources)

```bash
bash scripts/cleanup.sh          # asks first; --yes to skip the prompt, --all also deletes .local/
```
Removes the `healthqueue` kind cluster, containers labelled `project=healthqueue` (registry, LocalStack), the Compose
stack, the Trivy cache volume and local working folders. Other kind clusters and your default context are untouched.
