# Synthetic data and Excel workbooks

Both workbooks are **generated by code** from **reproducible synthetic data** (fixed random seeds), so anyone can
rebuild them and get identical numbers. Every metric cell is an Excel formula; a `Checks` sheet compares each formula
with an independent Python calculation.

## Regenerate everything

```bash
python scripts/generate_dora_data.py     # data/dora_deployments.csv   (seed 20261025, 2026-07-01..2026-09-28, 124 rows)
python scripts/generate_slo_data.py      # data/slo_daily_synthetic.csv (seed 20260901, September 2026, 30 rows)
python scripts/build_dora_workbook.py    # reports/dora-analysis.xlsx   (9 sheets, 41 checks)
python scripts/build_slo_workbook.py     # reports/slo-error-budget.xlsx (9 sheets, 14 checks)
python scripts/verify_workbooks.py       # structure + cached results check (any OS)
powershell -ExecutionPolicy Bypass -File scripts/verify_workbooks.ps1   # Windows + Excel: full recalc, error scan, saves values
```

Optional real measurement for the `Observed_Local` sheet (needs the kind cluster):
`python scripts/measure_slis.py` -> `reports/slo/local-load-test.json`.

No Excel? Open the files in **LibreOffice Calc** (free) - they recalculate on open (`fullCalcOnLoad`). Formulas use
only functions available in both Excel 2010+ and LibreOffice (no XLOOKUP/FILTER/dynamic arrays); medians by group use
classic array formulas `{=MEDIAN(IF(...))}`.

## `reports/dora-analysis.xlsx`

| Sheet | Content |
|---|---|
| Summary | 4 DORA metrics overall and last 30 days, cluster, trend, findings, recommendations, check status |
| Raw_Data | the 124 synthetic deployments (named ranges: `LeadTimeHours`, `ChangeFailed`, ...) |
| Metrics | formulas: frequency, median/p90 lead time, CFR, median/mean recovery, toil - overall and per phase |
| Weekly_Trend | 13 weeks with 4 charts |
| Benchmarks | DORA 2024 clusters (source cited), our thresholds, classification formulas, limitations |
| Failure_Analysis | failures by category and remediation; recovery-time chart |
| Toil_Reduction | toil per deployment by phase, hours saved, automation inventory |
| Definitions | metric definitions, units, windows, formulas, source |
| Checks | 41 formula-vs-Python checks |

## `reports/slo-error-budget.xlsx`

## Why these synthetic numbers?

The DORA data simulates three 30-day phases (manual -> CI -> GitOps) so the analysis has a trend to explain. The SLO
month has three injected incidents so the error budget policy has something to act on. Neither represents real
HealthQueue performance, and both workbooks say so on every data sheet.
